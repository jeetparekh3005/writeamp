# Decisions

Two genres live here: evergreen choosing frameworks (below), and dated ADRs for this
notebook's own stack (one file per decision, via the template). Frameworks get
re-compacted; ADRs never change.

Where *judgment* is stored. Two kinds of note:

1. **ADRs** - records of specific decisions, numbered `ADR-NNNN`, using the
 [template](./_template.md). Context → options → decision → consequences.
2. **Trade-off frameworks** - reusable *"X vs Y, when & why"* notes that outlive any single
 decision.

Frameworks to capture as they come up:

- [ ] SQL vs NoSQL vs NewSQL
- [ ] Sync vs async (REST vs events vs streaming)
- [ ] Monolith vs microservices vs modular monolith
- [ ] Strong vs eventual consistency
- [ ] RAG vs fine-tune vs long-context
- [ ] Agent vs deterministic pipeline
- [ ] Build vs buy vs API
- [ ] NL→rules: deterministic DSL vs LLM judgment
